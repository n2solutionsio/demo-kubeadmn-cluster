## Degrees used below

| Term | Meaning |
|---|---|
| **AI-authored** | Generated by the AI, then reviewed, tested and corrected by me |

| **Human-authored** | Written by me without AI |

## How AI was used

I directed the work, made the design decisions, and ran every command against my
own infrastructure. The AI drafted manifests and documentation, researched
current state (notably the `ingress-nginx` retirement and the Gateway API version
required by this Cilium release), and diagnosed failures from command output.

Several drafts were wrong and were corrected only because they were run against
real hosts rather than accepted as written. Two examples, both recorded in the
commit history: the container runtime was left with CRI disabled because a check
tested only whether a config file existed rather than what it contained, and an
`HTTPRoute` attached to every listener on the Gateway because its parent
reference was not pinned — which silently served the site over plaintext.

## External dependency

Node preparation is handled by
[`n2solutions.kubeadm`](https://github.com/n2solutionsio/ansible-collection-kubeadm)
— a public, MIT-licensed Ansible collection authored during this exercise with AI
assistance (**AI-authored**). It is disclosed here because
`docs/build-cluster.md` instructs the reader to install and run it, placing it in
the execution path of this submission.

It prepares hosts only: container runtime, kernel settings, swap, and staging the
Kubernetes packages. It does not install Kubernetes or create a cluster — both
are done manually, per the runbook.

## Not part of this submission

The infrastructure that provisions the virtual machines (OpenTofu, Terragrunt and
CI configuration) lives in a separate private repository and predates this
exercise, apart from the unit defining these three VMs, which was AI-assisted.
Extracts appear in `docs/infrastructure.md` as supporting context. That layer is
not required to reproduce the cluster.
